## 综合评估

成熟优势是内容生产：Lua、配置表、GUI、资源和开服工具连接较完整。技术风险主要是闭源边界、分支差异、版本隐式耦合、线程/编码约束和持久化行为不可见。区服权威进程加外围服务是本项目的模型；内部 AOI、线程调度和持久化细节不作未经验证的事实断言。

附件的评分是主观判断，保留原文用于背景，不作为供应商质量指标。基础系统“有”与“按我们的契约可调用、可审计、可恢复”是两个验收项。

附件的复用率 75%—90%、自主路线 30%—50%、兼容 API 的 20/60/20 分组均没有明确分母；当前改用逐组件清单、真实接口覆盖率和任务交付物，不引用这些百分比作为项目进度或预算依据。

## 工作量口径

- 原文独立内核路线：PC 原型 4—6 人/6—9 月，可运营 PC 6—10 人/12—18 月，三端 12—20 人/24—36 月，接近生态成熟度 20—30 人/3—5 年。属于历史经验估算，不能套用于当前复用路线。
- 当前官方内核路线：成熟版本迁移 3—5 月；从零内容产品 7—12 月；复杂原创和跨服 10—15 月。仅对有经验、授权/环境及时到位、范围受控的团队具有参考意义。
- 逐阶段时长若全串行约 43—65 周（见路线图）；7—12 月需要有条件的重叠开展，不能相加后仍声称按原短周期承诺。
- 当前尚无团队、官方包和实测数据；不设未经确认的具体上线日期。
