# 部署、观测与恢复

## 推荐拓扑

| 单元 | 起步部署 | 扩展方式 |
|---|---|---|
| 游戏区 | Windows VM 上官方 M2/网关/DB 或角色服务 | 按实测隔离、增加网关、多区，不任意拆分世界状态 |
| 游戏 SQL Server | 测试可同机，预发布/生产独立并按官方支持配置 | 容量与备份优先，HA 方案需验证连接/故障行为 |
| 跨服组 | 独立跨服 M2，配置/持久归属按官方规范 | 多活动实例或组，不能默认无限横向扩容 |
| ER 平台 | Linux 服务/容器，模块化单体 + 平台 DB | 先扩实例和 worker，按实测拆模块 |
| 资源 | 官方兼容的对象存储/CDN | 灰度入口、缓存验证与版本保留 |
| 观测/制品 | 集中日志、指标、告警与私有制品库 | 独立权限与保留策略 |

不在首期强行容器化 Windows M2。图中的 DB/角色进程数量是职责规划，实际安装包可能合并或拆分；所有资源规格、端口、许可证和服务账户待 M0/M1 清点。

## 网络边界

公开：官方客户端需要的网关端口、受限公共 HTTPS、资源 CDN。私有：M2、DB/角色服务、SQL Server、平台管理、跨服链路和部署控制。后台通过受控管理通道与强认证访问，不暴露数据库或任意执行入口。

只放行实际清点过的连接方向；如果官方授权必须外联，单独登记目的地与故障行为。端口、IP 和域名使用环境模板，不硬编码到玩法。密钥放环境密钥管理或受控 OS 文件，BOM 只引用秘密版本标识。

## 环境隔离

开发区可快速重置；测试区用于每次候选回归；预发布与生产保持配置结构和官方版本一致，使用沙箱支付及脱敏数据；生产独立凭据和部署权限。当前 macOS 工作区可完成文本/工具/平台工作，不能代替官方 Windows 验收。

一键启停顺序、健康检查和等待策略根据实际依赖图编写。PID 活着不等于可用；检查客户端登录、创建/重登、游戏状态和 DB 存取。自动重启有退避与次数限制，反复重启涉及资产故障时停止并报警。

## 监控指标

| 范围 | 可采集指标 | 告警依据 |
|---|---|---|
| 官方进程/OS | 存活、CPU、RSS、磁盘/IO、网络、日志错误 | 与稳定基线和资源余量对比 |
| 游戏链路 | 登录/重登成功率、往返延迟、在线/网关连接、队列（若可读） | 机器人探针与业务错误 |
| Lua | 自有入口耗时、错误、定时器积压/重复注册 | 热点/高分位与连续异常 |
| 数据库 | 连接错误、查询延迟、阻塞、空间、备份与恢复链健康 | 延迟/容量/备份新鲜度 |
| 客户端/资源 | 崩溃、帧率、内存、加载/下载失败与耗时 | 指定设备基线与真实分布 |
| 平台 | HTTP、worker 租约、outbox 积压、订单延迟、UNKNOWN 数 | 资产差异/未知结果优先处理 |
| 发布 | 各区 release、BOM 校验、部署结果、CDN manifest | 版本漂移与校验失败 |

M2 主循环、地图线程等内部指标仅在接口可得时采集；不可得时记录限制，以机器人响应和 OS/日志作代理，不把代理写成精确 tick 数据。

日志拟统一：UTC timestamp、environment、server ID、release ID、module、severity、request/trace/command ID、脱敏 player ID、duration、result code。不要把每个玩家 ID 做成指标 label，避免高基数；详细身份关联在受控日志中。

## 备份和恢复目标

首期拟定游戏/平台关键资产 RPO ≤ 15 分钟、单区 RTO ≤ 2 小时，**待成本、官方支持和实测确认**。资源/源码采用制品可恢复，不用混同数据库备份。若实测无法达到，调整方案并更新目标，不能标记达成。

建立完整/差异/日志链（SQL Server 支持且配置合适时），平台 DB 单独备份/PITR，备份异地、加密、访问审计。每天检查备份新鲜度/完整性；至少月度恢复至隔离实例，核对角色资产、订单、审计与运行版本，记录 RPO/RTO。恢复演练不得连接真实支付 worker。

## 故障处理要点

| 事件 | 即时动作 | 恢复证据 |
|---|---|---|
| M2 异常退出 | 停止依赖写操作/自动发货，保存日志和在途命令 | 重启后角色快照/未知命令核对 |
| DB 延迟/断开 | 根据已验证官方行为维护或限制写入，不盲目重启连锁服务 | 连接恢复、状态一致、备份链有效 |
| 平台故障 | 游戏基础功能继续按实测运行，暂停平台资产操作 | outbox 恢复与无重复发货 |
| CDN 错包 | 停止入口切换/灰度，恢复已验证 manifest | 冷缓存/热缓存客户端均可进入 |
| 跨服返回失败 | 冻结重复迁移和相关资产命令，检查唯一归属 | 单一有效角色归属、资产核对 |
| 资产差异 | 停止相关玩法，保护证据，人工/工具对账 | 根因、修复、回归与补偿审计 |

每个 runbook 实施时补触发条件、担当、具体命令、验证、升级路径和结束标准。故障后工作日志与风险登记同步，不仅记录“已重启”。

## 容量管理

先测单区与集中同屏，再决定网关/跨服/多区布局；标注硬件、进程组合、脚本负载、网络和资源版本。对同屏战斗、怪物寻路、Buff 和登录峰值分别评估。生产容量保留经实测确认的余量，不能用旧文档的线程数或 500 人建议作为 SLA。

## 运行组件与工程工作的责任划分

| 单元 | 复用范围 | 本项目工作 | 依赖/验收 |
|---|---|---|---|
| 每游戏区 | 官方 M2、1—N 游戏网关、DB/角色服务及游戏库；实际数量依交付包 | 拓扑/配置、许可/版本、启停/监控、维护和黑盒回归 | R01/R02、ENV01/ENV02 |
| 每跨服组 | 官方跨服 M2 及支持的归属/存储机制 | 分组、地图/活动配置、进入/返回/故障核对 | X01—03 |
| 官方在线服务 | 可用的授权、账号、充值、GM/工具服、反外挂、CDN | 账号/权限、接口接入、审计、故障/退出说明 | R08、P02—07/C05 |
| 自有平台 | 成熟 OS/容器、数据库、可选缓存 | 仅部署必要模块、持久命令与对账流程 | P01—07，按复用差异裁剪 |
| 监控/恢复 | 现成采集/日志/告警、数据库原生备份与恢复工具 | 采集配置、关联字段、告警阈值、备份脚本、隔离恢复/对账 runbook | ENV03/OPS01/OPS02 |

游戏区数量与数据库实例数量不等同：测试可合并，正式按隔离/容量/官方支持决定，不先规定一服一独立 SQL 机器。授权外联、官方后台与 CDN 是供应商服务依赖；Windows 游戏组件不是 Linux 外围服务，故障和更新边界分别记录。

一键部署针对已取得许可/包的标准环境；许可办理、下载、签名和官方人工步骤不算自动部署已实现。恢复目标须用真实角色/订单核对和已测时间验收，备份命令存在不能标 ENV03/OPS02 完成。
