# 自有消息契约与安全边界

## 传输边界

不重写官方游戏网络协议。自有消息使用锁定版本支持的 LuaNetMsg 或 SubmitForm；传输适配层负责映射，不让玩法模块自行拼接脚本路径与函数名。现阶段仅有设计，未注册真实消息号。

官方[SubmitForm 文档](https://engine-doc.996m2.com/web/#/29/317)说明客户端提交文件、函数和参数，并警告参数改包风险。本项目只允许固定的业务入口和函数白名单，不按客户端输入动态加载任意文件/执行任意方法；能使用消息 ID 的模块优先用注册表路由。

## 逻辑消息格式（拟定）

```json
{
  "schema_version": 1,
  "request_id": "opaque-string",
  "message_name": "activity.claim",
  "config_version": "release-table-version",
  "payload": {"activity_id": "id", "period_id": "period"}
}
```

响应包含 `request_id`、固定 `code`、业务 `data` 和可选 `retry_after_ms`；显示文本在客户端映射。实际序列化类型、消息号/大小、字段数量和大整数编码由 R03 探针确定，逻辑示例不要求官方直接支持 JSON。

身份来自服务端连接/玩家上下文；客户端自带的 player/server/account 字段只能作为显示或一致性校验，不能切换操作对象。`request_id` 用于追踪与传输去重，真正一次性领取依赖服务器生成的业务键和持久结果。

注册表字段：逻辑名称、实际传输类型/ID、方向、schema version、payload schema、权限、限流、幂等语义、兼容范围、响应错误码、负责人。消息 ID 必须避开官方保留区，范围在 M0 核实。

## 服务端入口步骤

1. 识别来源、当前角色/区服归属与会话状态。
2. 验证消息/函数白名单和版本；不支持则返回升级/刷新提示。
3. 校验 payload 长度、字段、字符串编码、枚举、整数、范围、嵌套层数；拒绝多余字段或按 schema 明确兼容策略。
4. 检查权限、等级、地图、活动窗口、库存/余额、数量、冷却及状态，全部从服务端读取。
5. 按账号/角色/会话/操作限流，保护后端队列；超限不消耗材料。
6. 生成业务键并执行受控原子操作，或记录结果未知等待核对；不允许“先发后记”补偿伪装成幂等。
7. 返回结果，记录审计及耗时，客户端再更新展示。

错误码初始集合：`INVALID_ARGUMENT`、`UNAUTHORIZED`、`FORBIDDEN`、`VERSION_MISMATCH`、`STATE_CONFLICT`、`RATE_LIMITED`、`DEPENDENCY_UNAVAILABLE`、`RESULT_UNKNOWN`、`INTERNAL_ERROR`。未知结果表示没有证据判断是否成功，不可自动再次执行资产操作。

## 不可信输入检查

负数/小数、NaN/Infinity、超大整数、空参数、非法 UTF 字节、重复字段、路径穿越、空字符、重复封包、旧 schema、跨账号目标、重登后旧请求、过期活动和跨服归属变化均进入测试。价格、伤害、奖励、掉落与余额不能由客户端决定。

官方 Lua 对 `load`、`dofile`、`os`、文件和 HTTP 的支持不等于自有模块可以任意使用；在自有调用入口限制动态加载、路径和目标，避免破坏官方全局运行环境。

## 游戏到平台桥接

优先 HTTPS、服务身份与最小权限；认证签名覆盖方法、路径、时间戳、nonce 和 body hash，平台控制重放窗口、nonce 去重和密钥轮换。如果官方 API 不支持认证头/HTTPS，则在同机或专用受限网络中部署经过验证的桥接代理，代理只暴露固定操作并绑定可信来源；不可把长期密钥塞入 URL。

接口限制超时、payload 和并发、队列长度；日志不记录密钥/完整凭据。采用固定域名/地址白名单，禁止客户端影响桥接目的地；防止 SSRF。代理、认证与回调线程能力未验证前，不接入真实支付和远程 GM 写操作。

## 账号、GM 与支付

- 渠道身份由平台验证并映射到官方账号接入能力，不私建绕过登录认证的路径。展示 API 与资产 API 分开鉴权。
- 支付回调核验渠道签名、订单、金额、币种、商户、交易状态；可信服务端确认支付，客户端提示不参与发货判定。
- GM RBAC 拟分只读客服、内容运维、资产处理、部署管理员；高风险操作强认证、明确角色/区服、原因和审计。正式操作按权限策略执行，不能把开发角色默认授予生产写权限。
- 发奖、封禁、退款处理、配置发布有命令状态和结果查询；日志无法证明到账时不能显示成功。

## 反外挂与风控

复用官方反外挂，但业务仍执行服务端边界检查。规则观察移动/攻速/拾取/交易/领取频率与不可达状态，结合延迟和官方同步特性；先告警与证据，误报评估后再开启自动措施。客户端完整性/混淆仅是辅助能力，不能替代权威判断。

安全验收以实际用例为准：任意表单调用被拒、越权目标被拒、重复领取与重复回调不增发、秘密不在包/日志中、GM 审计可追踪、依赖故障不会放宽校验。具体发行合规由相关业务/法律专业支持确认，本文件只设计工程控制。
