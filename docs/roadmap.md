# 完整实现路线图

## 实施原则与估算

先文档和契约，再验证官方能力，再做标准环境/工具链，再用垂直切片打通，再扩内容、多端、平台、跨服与商业交付。每个阶段按退出证据验收；后继工作可准备但不能跳过依赖标记完成。

当前文档基线 0.2 已完成（含 DOC05 复用/开发分工），M0 运行接入尚未完成。新增 R07/R08/SPEC01 将原隐含工作显式分解，不改变原估算口径；后续按覆盖结论与实际工作量重估。下表以附件有经验团队的周数为参考，不是 Codex 单独工作的交付承诺。按全串行总计约 **43—65 周**；充分利用工具/平台/内容等可独立工作，范围稳定且外部交付及时才可能落在原方案 **7—12 个月**。复杂原创/跨服参考 **10—15 个月**。阶段周数不包含无法预测的许可/采购等待，不设虚假日历日期。

## M0：立项清点与官方能力，2—3 周

**当前：文档部分已完成，运行接入待开展。**

输入：用户已确定复用路线；尚需官方分支/交付包/许可、Windows 测试环境。

工作：DOC01—03 文档基线；DOC04 Git 初始化及文档推送；DOC05 全文复用/开发分工；SPEC01 切片规格草案；R01 清点组件、许可与哈希；R02 空白区服和客户端启动；R03 Lua/消息/HTTP/GUI/编码探针；R06 奖励持久化与原子能力探针。R07 切片基础系统覆盖/差异；R08 初步官方服务/许可清单。记录未知能力和平台交付范围。

交付：官方版本矩阵、进程/端口/配置图、首个 BOM、能力矩阵和探针报告、最小角色保存证据。文档原文与来源可追溯。

退出：R07 对切片必需系统有锁版覆盖/差异结论，R08 已列服务/授权与未知项；一个锁定组合稳定重复启动；PC 能登录、移动、战斗和重登保存；交付包有两端时验证两端同服。无法获得第二端时记录缩小的 M0 范围并在 M5 验收该端。发货能力允许不满足，但必须有明确结论，不可将 R06 未知结果填成通过。

## M1：标准环境与运行时适配，3—4 周

输入：R01—03；可先离线设计 R04/T01。

工作：ENV01 开发/测试/预发布模板；ENV02 启停、健康检查、干净机复现；ENV03 官方 DB 初始化/备份恢复；R04 ER runtime 实现；R05 注册/对象生命周期；OPS01 基础日志指标。

交付：可重建环境、受控 runtime 适配、配置模板、启停 CLI/脚本、备份与恢复报告、环境 BOM。

退出：不含许可办理/下载的新机部署目标两小时内；重复启停无注册堆积；官方对象离线/切图/重载安全；备份能在隔离区真实恢复。所有指标是已测数据，不以安装脚本存在代替运行验收。

## M2：开发工具链与发布基线，4—6 周

输入：T01 可立即开始，其余根据 R03/ENV01/官方工具能力接续。

工作：T01 工程骨架与开发命令；T02 schema/Excel/CSV；T03 ID/消息注册；T04 编码；T05 资源清单；T06 官方转换/构建封装；T07 BOM；T08 CI；T09 测试部署/回滚；QA01 契约自动验收。

交付：好/坏样本、明确错误报告、可追踪服务器/客户端包、资源包、不可变 BOM、测试区部署与回滚证据。

退出：校验能定位坏表/脚本/资源；双方公共表一致；无手工复制自有发布文件；官方 GUI 必需人工步骤若存在则显式登记，不能虚报全自动；正式候选由唯一 release 关联全部制品。

## M3：PC 垂直切片，6—8 周

输入：M1/M2 关键链路；平台技术/沙箱可提前准备。

工作：SPEC01 切片规格/分工、R07/R08 对应能力；V01 一个职业三张地图及基础内容；V02 自定义 UI/消息；V03 玩法与资产状态链路；V04 真实热更新；P01—04 官方服务接入与必要差异沙箱模块；V05 沙箱端到端；QA02 核心回归；C01 PC 体验。

交付：`0.1 Ash` 候选包、安装/试玩步骤、真实保存/重登/热更证据、沙箱订单与发货报告。R06 不满足时，沙箱记录结果限制，相关高价值功能不开放。

退出：角色从进入、成长、战斗、拾取、任务、购买、退出到重登可完整重放；至少一个自有 UI；一次实际热更新；关键失败与重复请求可处理。SPEC01 确认后续玩法量、容量目标、发行平台与渠道，形成商业范围基线；R07/R08 对切片纳入的内置/平台能力有证据，自有代码仅覆盖差异。

## M4：核心玩法生产，10—16 周

输入：M3 通过及 SPEC01 商业范围基线，R07 对应系统子项已验证。

工作：G01 职业/技能/成长；G02 装备/合成/养成；G03 Boss/副本/活动/赛季；G04 经济/商城/排行；G05 行会社交/引导/挂机规则；QA02 随模块扩回归，P07 统计事件。

交付：玩法规格、版本化内容、经济边界与异常用例、可持续扩展 UI/资源、内容回归库。

退出：范围内机制/配置/自有差异分工均有报告，R07 商业系统相关项已验收；核心玩法完成、无 P0/P1 资产与核心链路缺陷；不以地图/物品总量替代规则正确性。官方内置社交等只做适配和验证，避免二次造系统。

## M5：多端与资源发布，6—10 周

输入：稳定客户端契约；与 M4 的非同区域代码可交错开展。

工作：C02 Android、C03 iOS、C04 渠道 SDK/签名/账号、C05 首包/微端/静默/弱网；V04 扩展热更与 CDN 灰度；C01 PC 对应输入适配。

交付：实际可发行的目标端候选包、设备矩阵、性能/内存/弱网报告、SDK 与资源发布说明。H5 仅在新范围决定中加入。

退出：R08 资源/反外挂等纳入服务子项有许可/接入证据；目标端均真实登录/游戏/更新/断线恢复；后台切换和安全区域通过；发行账号/签名/权限等依赖有结论。不可获得的平台标记依赖，不用模拟器测试冒充全量设备测试。

## M6：跨服、商业平台与可靠性，6—10 周

输入：运行/消息/资产能力已验证；R08 完成相关官方平台/后台契约评估，跨服与支付分别按依赖推进。

工作：X01—03 跨服拓扑/活动/失败恢复；P03/P04 真实渠道与发货门槛；P05 CDK；P06 GM/客服/RBAC；QA03 机器人；QA04 压测；QA05 故障注入；OPS02 恢复演练；OPS01 告警完善。

交付：跨服归属与资产报告、支付补单/对账、受控后台、容量报告、故障 runbook、实际 RPO/RTO。

退出：R08 对纳入官方服务完成权限/查询/审计/故障验收，同一订单单一发货链；跨服无重复归属/资产；支付重复、延迟、乱序与崩溃窗口满足发货契约；未知结果可定位；高风险 GM 可审计；容量与恢复目标经报告确认。真实支付不满足门槛时不能转入付费封测。

## M7：封测与上线，6—8 周

输入：M4—M6 对应产品范围验收完成。

工作：L01 删档封测及条件满足后的付费封测；OPS03 灰度/回滚演练；L02 正式发行与上线；缺陷、经济、设备和安全问题收敛。

交付：封测结果、容量边界、上线检查单、版本/数据库/资源兼容报告、恢复与回滚报告、值守/客服流程。

退出：无未解决 P0/P1；真实环境与账号条件满足；发布/恢复证据齐全；正式候选 BOM 冻结；上线后观察符合稳定基线。上线是外部动作，按届时用户授权执行；当前任务只建立计划。

## 当前可开始的首轮实现

1. SPEC01 离线部分：整理切片规格、功能分工、源表/消息/资源需求；不虚构完整商业数值。
2. T01：建立自有源码骨架、版本化配置格式、开发 CLI 和最小文档检查命令。
3. T02/T03/T04/T05/T07：制作最小好/坏样本并实现 schema、ID、编码、路径、BOM 校验，不依赖官方运行包。
4. R04 离线部分：先写 ER 契约与 fake runtime；官方适配留待探针，明确 mock 状态。
5. P01：平台选型小探针与事务/outbox 原型；不提前连接支付生产渠道。
6. R01/R02：获得包和环境后清点并真实启动，开展 R07/R08 覆盖评估；按子能力触发 ENV/T06/QA01 与对应 V/G/P/C 集成。

核心依赖链是官方交付 → 锁版环境/探针 → 官方构建/测试部署 → 垂直切片 → 资产/跨服/多端可靠性 → 封测上线。工具、规格、样本与离线逻辑不需要等待所有外部条件。

## 范围与里程碑变更

新需求必须关联任务、影响阶段、前置能力、验收和成本；改变路线记录 ADR。进度只有证据满足退出条件才改为“完成”；如果只完成某个端或模块，保留其余依赖而不是跳过。每轮工作同步[任务](backlog.md)、[进度](progress/README.md)与[日志](progress/worklog.md)。

## 每阶段的复用与开发交付

| 阶段 | 官方/通用能力复用 | 本项目工作 |
|---|---|---|
| M0 | 官方包、许可、空白系统与平台服务 | 清点/探针/覆盖差异、切片规格；文档不代替接入 |
| M1 | 官方进程、基础库、OS/备份工具 | 环境/启停/健康封装、runtime/生命周期、真实恢复 |
| M2 | 官方转换/GUI/打包、Git/CI/制品服务 | schema/ID/编码/资源校验、工具封装、BOM/部署/回滚 |
| M3 | 角色/战斗/地图/资产/账号/热更机制 | 最小内容、差异脚本、一个 UI、沙箱接入与组合报告 |
| M4 | 原生技能/物品/社交/经济/活动 | 范围内数据/资源、差异规则/UI、经济边界与回归 |
| M5 | 多端原生包、SDK、官方下载链路 | 布局/操作/渠道配置、弱网/设备/灰度验收 |
| M6 | 跨服、官方商业后台、监控/备份工具 | 活动规则、必要平台差异、审计/对账、容量/故障演练 |
| M7 | 已验证的运行与发布基础 | 封测、缺陷收敛、真实发行、上线观察和交接 |

路线 B 无当前阶段交付；M7 后持续运营 6—12 个月再结合真实限制评估，不把该观察期计入已完成进度。成熟合法版本迁移参考 3—5 个月，仍须做 API/配置/资源/授权与数据差异评估；当前未提供成熟底板，不套用迁移周期。
