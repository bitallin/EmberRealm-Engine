# ADR-0002：单仓库、工具优先与平台选型

- 日期：2026-10-08。
- 状态：单仓库、离线优先、平台模块化单体已采纳；具体语言/版本为拟定，待 T01/P01 探针确认。

## 背景

项目目前只有文档，无既有技术栈；官方运行时暂不可用。起步工作应能在当前 macOS 执行，同时在 Windows 官方工具上复现。过早拆仓/拆微服务增加版本协调成本。

## 候选与决定

- 工具采用 Python 方向：适合 CSV、编码、hash、schema、进程封装和报告；先标准库/少量锁定依赖。Node 也能完成，但暂无 UI 工具生态必须共享的理由。
- 平台拟 Go + PostgreSQL：适合独立 API、worker 和事务/outbox，减少运行依赖。Python/TypeScript 可替代，若探针发现团队维护或官方集成成本明显更低，可以通过新 ADR 修改。
- 后台 UI 拟 TypeScript/React，仅在 P06 具体流程确认后建设，不影响先做 CLI/报告。
- 单仓库与统一 BOM：源模块一处登记，官方制品/大资源放独立受控存储，不在 Git 内混放。
- 起步平台为模块化单体；可选 Redis 不是真值，DB outbox 先承担可靠投递。

## 验证门槛

T01 验证跨平台 CLI、依赖锁和开发命令；P01 验证订单/唯一约束/outbox/租约/崩溃恢复原型与测试。记录精确版本、许可证、运行方法和限制。仅探针通过后把具体技术改为已采纳；当前未安装或运行这些实现。

## 后果

形成少量可维护组件；需要两种开发运行时，但官方集成仍需独立 Windows Runner。若增加新语言/中间件，必须说明需求与运维成本。关联[选型基线](../technical-route.md)、[工具链](../tooling-release.md)及 P01/T01。
