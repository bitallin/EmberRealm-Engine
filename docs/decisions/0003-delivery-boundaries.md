# ADR-0003：按交付物划分复用、配置、适配与自研

- 日期：2026-10-08（Asia/Shanghai）。
- 状态：已采纳；文档分工完成，运行与实现待开展。
- 依据：用户本轮要求按官方内核同构方案完整完善文档，划清直接复用与开发。
- 关系：细化 ADR-0001/0002，不替代其路线和选型；平台技术仍待探针。

## 背景

单列“玩法开发”容易被理解为重新实现战斗、背包、社交；单列“外围平台”容易默认账号、支付、GM、CDK、公告全部从零建设。实际同一功能常由官方机制、产品数据、自有差异规则和接入验收共同组成。

## 决定

以[复用与开发边界总表](../reuse-development-matrix.md)统一交付分类：复用、配置、适配、自研、后置。任务工作类型与验证状态分开记录。已有机制优先复用，数据必须制作，差异先配置/API/Lua/UI，跨区及必要外围能力才交给服务。

增加 R07 逐内置系统覆盖/差异验收、R08 官方平台与授权服务契约评估、SPEC01 产品规格及功能分工。P02—07 按评估结果交付接入或必要自有模块；满足需求的官方服务不再重建第二套。支付只选一条受控发货链，自有订单/审计映射不能与官方链路并行重复发奖。

工程自研集中在校验、契约、BOM、流程与集成脚本，复用现成 Git/CI/监控/数据库备份等通用工具。无官方包时可完成规格与离线工具，不能确认运行能力。

## 后果与验收

R07/R08 需要锁版、许可、公开接口、差异、失败恢复及证据，不因供应商产品列表就标完成。SPEC01 允许先做切片草案，商业内容量和渠道仍待确认。改为外围自研需写明未覆盖需求与可验证契约；改内核须新 ADR。

验收分别证明官方机制、自有差异和组合运行。影响：技术路线/架构、Lua/内容/平台/数据/工具/运维/测试、任务/路线图、能力模板与发布检查单；DOC05/W003 记录本轮文档交付。
