# 工具链、构建与发布

## 工具交付顺序

先做无需官方环境的 schema/ID/路径/编码检查及 BOM 生成，再封装官方转换、打包与部署。拟定统一 CLI `erctl`（未实现）：`validate`、`build`、`bom`、`deploy`、`status`、`rollback`。实现可先用 Python 模块入口，名称不是必须先发布的独立产品。

所有命令有明确输入、输出、退出码、日志和 dry-run；部署/回滚与只读校验分开，目标环境显式指定，不默认生产。外部工具调用记录版本、输入哈希、输出哈希、退出码和耗时。

## 校验流水线

| 检查 | 失败条件 | 证据 |
|---|---|---|
| Lua | 锁定语法不支持、缺模块、入口/消息冲突、自有代码危险动态入口 | 文件/行/规则/引擎版本 |
| 编码 | 非法 UTF-8、目标字符集无法表示、往返不一致 | 字符、位置、源/目标编码 |
| 数据 | 字段/范围/外键/ID 不合法，公共表投影差异 | 表、行、列、schema version |
| 资源 | 路径缺失、大小写/Unicode 冲突、非法路径、超出预算 | 资源路径、来源、hash、大小 |
| 消息 | 官方保留冲突、schema 不匹配、未登记路由 | 消息名、ID、方向、版本 |
| 版本 | M2/client/DB/tool/Lua 契约组合不受支持 | BOM 与能力矩阵差异 |
| 制品 | 必需文件缺失、hash 不符、密钥/测试数据混入 | manifest 和检查报告 |

错误直接定位输入，不用“打包失败”替代根因。GB2312 失败不能自动降级 GBK。开发检查可只运行相关部分，发布必须全量检查。

## 构建步骤

1. 读取源码版本与锁文件，检查工作树状态；正式候选制品禁止混入未登记变更。
2. 验证源表、资源清单、协议与官方能力组合。
3. 转换 Excel/CSV 为确定性中间数据，再交官方表格工具；生成客户端只读表/服务器配置。
4. 处理 GUIExport、客户端 Lua 和服务端严格编码转换，输出各自清单。
5. 使用锁定官方资源打包工具生成 DEV/首包/热更/静默包；不假定所有步骤都有 CLI。
6. 生成 manifest、hash、API/表/协议摘要与 BOM，归档输入、报告和制品。
7. 签名/访问控制应用到自有发布元数据；客户端是否验证自有签名必须有能力证据，不能仅服务器签名就称客户端已验证。
8. 部署隔离测试环境并记录 release ID，执行契约与关键场景回归。

官方工具非确定性产物需记录原因、完整制品哈希及可重复的输入，不声称字节级可重现。不可自动化 GUI 流程使用受控人工操作记录与产物校验，之后再替换封装。

## BOM 与依赖锁

[BOM 模板](templates/release-bom.example.yaml)区分 `planning` 与 `validated`。模板中的 null 是未确定，不允许正式构建沿用。release ID 唯一且不可覆盖，记录分支、精确官方版本/制品哈希、DB schema、脚本/平台源码、表/资源/消息、目标编码、迁移、测试证据和兼容区间。

构建/发布校验规则：必填未确定就失败；hash 格式真实；源码 revision 可解析；工作树状态已登记；基础热更版本存在且兼容；数据库迁移符合前置条件；能力矩阵验证的是同一官方组合。尚未初始化 Git 时，只能做设计/本地草案，不能声称发布制品已具备 commit 可追踪性。

## 环境与流水线

macOS/Linux Runner 可做静态检查与平台构建；Windows Runner 负责官方工具和游戏集成。官方制品与凭据从受控存储注入，不打印到日志。开发/测试/预发布/生产分别持有配置与密钥，部署身份最小权限。

分支策略拟定为主干加短分支；主干保持可验证，受支持 release 以标签归档。CI 平台待仓库托管确定，选型不阻塞本地 CLI。每个发布制品有源码版本与流水线 ID，测试报告与制品同库归档。

## 灰度发布与回滚

发布前完成检查单：备份、兼容报告、制品校验、容量余量、监控与回滚目标。资源先上传并验证 CDN 命中/哈希，再开启测试入口；服务器按官方支持维护方式更新，登录入口最后切换。客户端旧版本行为在预发布测过才能设置升级门槛。

灰度从测试区到有限区服/渠道，再扩大；跨服组需要一起核验兼容。阈值依据基准确认：登录失败、游戏/客户端错误、资源下载、主循环/代理指标、订单未知状态和资产差异。资产差异立即停止相关写功能并核对，不等待普通错误率阈值。

回滚分层：脚本/资源回滚必须保持数据库与消息兼容；配置不能因版本退回破坏已发资产；官方内核和 DB 升级按整组计划处理。数据库不可逆变更只允许前向修复或演练过的恢复，记录停服窗口、可能数据损失和对账。不能把覆盖旧文件称为完整回滚。

## 供应链与制品保留

登记官方包、开源依赖、资源的来源和许可；锁依赖并校验 hash。许可/密钥文件独立管理。制品至少保留当前稳定版本、上个稳定版本、所有在支持期内候选版本及关联备份引用；精确保留期在环境成本和业务要求明确后确认。
