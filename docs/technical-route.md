# 技术路线与组件复用

## 两阶段战略

**路线 A 已采纳**：官方运行时作为边界明确的设备，保留 Lua、M2、配置表和资源工作方式；自有代码构建适配层、内容生产与发布平台。所有官方组件复用以取得对应交付包、许可和接口验证为前提。

**路线 B 仅预研**：运行 6—12 个月后或遇到经实证的重大限制，评估独立内核。保留可用业务契约、数据和资源流程，整体替换客户端/协议/网关/M2；不预先承诺任意旧版本行为完全一致。[ADR-0001](decisions/0001-runtime-reuse.md)记录当前选择。

## 组件处理方式

| 组件 | 策略 | 本项目需要做的工作 |
|---|---|---|
| M2、登录/游戏网关、角色/DB 服务、控制器 | 官方复用 | 清点、锁版、启停、监测、故障处理 |
| 原生客户端、网络与地图/角色渲染 | 官方复用 | 交付确认、包/SDK 接入、黑盒回归 |
| Lua/LuaJIT | 官方内置 | 语法与能力探针、生命周期规范，不自行升级运行时 |
| GUI 编辑器、`SL:*`/`GUI:*` | 官方复用加适配 | 把 GUIExport 与自有行为拆开，多端 UI |
| 角色、战斗、物品、AI、地图、背包、Buff | 内置优先 | 内容配置、行为验收、少量 Lua 扩展 |
| 行会、组队、邮件、商城、排行、拍卖 | 内置优先 | 逐版本确认，缺项再适配，不默认都能无成本使用 |
| 跨服 M2 | 官方复用加业务 | 拓扑、进入/返回、异常状态与活动规则 |
| SQL Server 核心库/迁移 | 官方规范 | 锁定 schema、备份、官方迁移和恢复，不改字段语义 |
| 资源转换、压缩、表格转换、热更新 | 官方工具优先 | CLI/人工边界核实，输入输出清单、自动化封装 |
| GM、工具服、反外挂、CDN | 条件复用 | 验证许可与接口，补足本项目权限、审计、规则和版本管理 |
| Lua 玩法、任务、养成、活动 | 自有开发 | 模板、领域规则、配置、测试 |
| 工程工具、契约、BOM、CI/CD | 自有开发 | 校验、构建、发布、回滚、证据 |
| 账号映射、支付、CDK、客服、分析 | 自有模块 | 独立平台数据，通过受控游戏桥接写入游戏结果 |
| 原创资源/地图/内容 | 自有或许可获得 | 来源登记、格式转换、性能与再分发范围 |

官方内置能力存在不代表无需验证；能配置解决时不用外部服务复制其状态。

## 选型基线

| 层 | 基线 | 决策边界 |
|---|---|---|
| 区服 | Windows Server + 官方二进制 | Windows/SQL 具体版本等待官方兼容表；不先强制容器化 |
| 扩展 | 官方支持的 Lua/LuaJIT；自有代码先按 Lua 5.1 兼容子集 | 精确语义由探针确认，避免直接依赖 5.3 整数/位运算语法 |
| 客户端 | 官方原生层 + Lua/GUI | PC 先验收，Android/iOS 随交付接入；H5 可选 |
| 工具链 | 拟用 Python 3.12+，开发与 Windows Runner 锁同一小版本 | 版本是工程基线建议，尚未安装/验证；CLI、JSON/YAML、CSV、哈希、编码检查优先 |
| 平台后端 | 拟用 Go + PostgreSQL 的模块化单体 | 待 P01 选型探针通过再锁具体版本；一套服务内分模块，先不拆微服务 |
| 平台前端 | 拟用 TypeScript/React | 后台有实际需求时立项；先 CLI/报告，减少前置工作 |
| 缓存/队列 | 可选 Redis；持久任务先用平台 DB outbox | Redis 不承担资产真值，不为起步强加队列集群 |
| 静态表 | Excel 编辑 → 确定性 CSV → 官方目标格式/客户端 Lua | 统一 schema/ID；生成件不可手改 |
| 发布资源 | 受控制品存储 + 对象存储/CDN | 官方资源格式/校验机制优先，未实测不宣称支持自有签名 |
| 观测 | 结构化自有日志 + 供应商日志采集，指标/告警平台按接入成本选定 | 不假定 M2 暴露内部 tick 指标 |

工具与平台技术仅是减少实施歧义的拟定方向。先做最小技术探针，再生成依赖锁与 ADR；不因本文件新增组件而立即搭建全部服务。选型理由与替代项见 [ADR-0002](decisions/0002-tooling-platform.md)。

## 扩展优先序

配置 → 官方 API → 自有 Lua → 客户端 Lua UI → 受控外围服务 → 向供应商确认新增能力 → 重新评估内核。

每项需求记录：内置是否覆盖、差异、公开接口、实测限制、最小扩展方式、故障与回滚。不因未知接口而直接重写模块。

## 内核替换门槛

当授权与发行要求不匹配、无法取得必要控制权、已测容量不达标、关键平台/玩法无法实现、安全边界无法满足或供应商持续维护不可接受时，建立替换提案。提案需有复现实例、替代方案、兼容范围、成本、测试与迁移计划，不能仅凭风格偏好立项。

路线 B 应先列可保留的自有 API/数据，建立行为用例库，再分别验证地图、移动、AOI、战斗、Lua、持久化和客户端原型；待端到端候选链路通过后，选择测试区整组替换。正式区不长期混用新客户端与旧私有网关协议；不再依赖旧授权体系也必须使用自主且合法取得的资源和代码。
