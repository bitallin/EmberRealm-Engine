# Lua、玩法与客户端技术细节

## 模块规则

自有业务命名空间 `ER`；优先 Lua 5.1 兼容子集，实际 LuaJIT/数值/JSON/位运算由锁版探针确认。避免 Lua 5.3 专属语法、全局污染、隐式跨模块写变量和依赖非公开对象字段。

建议模块：`er.bootstrap`（入口）、`er.runtime`（官方适配）、`er.contracts`（校验）、`er.domain.*`（业务）、`er.handlers.*`（事件）、`er.observability`（日志）、`er.config`（只读配置）。模块名为拟定，不保证官方 `require` 可直接接受所有目录布局。

玩法事件先做边界校验，再调用领域规则；领域返回受控命令，由 runtime 执行。官方对象不进入长期缓存、队列或跨线程任务；存 player ID、活动 ID、版本号，执行时重新获取上下文。

## 初始化与生命周期

1. 验证配置/消息/schema/BOM 是否匹配。
2. 加载 runtime 能力清单，必要能力缺失则禁用对应模块并报告，不尝试调用未知 API。
3. 构建只读表、业务路由、事件和定时器注册表。
4. 按官方实际生命周期绑定一次；多次加载要避免重复定时器/重复发奖。
5. 函数异常边界记录 request ID、玩家 ID、模块版本和错误，入口返回固定错误码；错误日志脱敏。
6. 停机/重载登记在途高价值命令。不能用 `pcall` 掩盖资产部分成功。

时间规则：服务端业务时间为权威；持久化 UTC，运营按 Asia/Shanghai 显示。冷却尽量采用支持的单调时间源，若只能墙钟则验证时钟回拨行为。定时任务使用“周期/玩家/活动”持久业务键；离线补偿和跨午夜领取语义写入玩法规格。

随机规则：官方掉落优先；自有规则明确 RNG 来源与初始化。重载时随机种子/序列行为需验证，不让客户端提供中奖结果。随机回归用固定测试种子，生产不要以可猜客户端输入当种子。

## 数值与经济

- 金额、数量、次数使用有界整数；先验证有限数、整数性、正负与上限，再运算。超大 ID 以字符串传输，避免 Lua 双精度和 JavaScript 精度问题。
- 奖励/价格/配方由服务端当前配置决定，客户端仅提交 ID、数量和意图。
- 乘法、累计奖励和批量合成设上限，拒绝溢出/精度丢失/NaN/Infinity。
- 配置 version 随请求关联；服务端对已过期配置返回可刷新错误，不按客户端传来的旧价成交。
- “扣材料并给装备”“扣货币并购买”先复用内置原子玩法/公开原子 API；否则在 R06 明确验证所有崩溃窗口，再决定是否开放，不能靠内存锁声称安全。

## 示例玩法规格

垂直切片先建一个 NPC 任务和一次受控活动领取。每个玩法文档应含入口、条件、数据字段、奖励源、重复请求、离线、重登、重载、跨服、配置升级与审计。示例：`activity_id + period_id + player_id` 是领取业务键；是否可原子记录该键和奖励取决于官方能力，未解决时仅用于低价值测试场景。

## 客户端分层

GUIExport 保留编辑器生成内容；GUILayout/自有 `client-lua/er` 编写行为。视图只负责绘制与事件，状态模型处理服务器快照/增量，消息路由做 schema 校验和错误显示，runtime 封装 `SL:*`/`GUI:*`。

页面生命周期：创建 → 绑定 → 请求数据 → 渲染 → 隐藏/销毁 → 注销事件/定时器。进入两次、关闭后收到回包、切账号、重连与热更后必须无重复回调和对象泄漏。

界面状态至少包括加载、成功、空数据、网络错误、版本不兼容、操作处理中。点击后禁用/去抖只能改善交互，服务端仍需幂等和限流。红点和展示缓存以服务端结果刷新，不把本地“领取成功”当作最终资产落库。

## 多端与资源

- PC：鼠标、键盘快捷键、悬停提示、窗口/分辨率、输入焦点。
- Android/iOS：触屏、拖拽阈值、安全区域、横竖屏约束、后台切换与恢复、设备内存。
- 同一业务契约，两套布局参数；资源路径规范化，不假定 PC 的大小写行为适用于其他平台。
- 首包含关键 UI/前期地图与必要提示；可延迟大资源用官方分包/静默策略。缺失资源显示可恢复占位并报告，不崩溃或误报交易成功。
- 不实现原生渲染/寻路/协议；这些能力走官方组件并纳入黑盒体验回归。

## 测试要求

离线测试领域边界与固定输入输出；官方集成测试对象生命周期、UI 销毁、同服互动、消息大小、重载与保存。代码分析识别自有代码中的危险动态加载/路径拼接；不擅自修改官方全局环境而破坏官方模块。覆盖新玩法正常/重复/非法/故障场景，不为每个薄封装编写镜像测试。

## Lua/UI 的开发清单与继承边界

| 工作 | 处理与交付 |
|---|---|
| 普攻/技能/Buff/掉落/装备/社交基本行为 | 官方机制+源表；公开 API 只在必要事件和差异规则处调用 |
| NPC、任务、养成、Boss/副本/活动/赛季新规则 | 内置能力覆盖后，仅差异写 ER 领域模块；对应配置/schema 与用例同时交付 |
| 登录/地图/角色/背包等基础 UI | 默认继承官方 UI；覆盖点、脚本/资源许可先由 R07 确认 |
| 活动/养成/支付展示/自定义排行 | 官方 GUI 控件与导出布局，自研页面行为、红点/状态/错误与引导 |
| SL/GUI、SubmitForm/LuaNetMsg | ER 客户端/服务端适配+消息契约；不重写传输或用任意函数名调用 |
| PC/Android/iOS | 原生客户端复用；布局、触控/鼠标、资源引用和设备回归由本项目完成 |

生成 GUIExport 不手改；官方开放/可覆盖的 Lua 文件保留来源与差异，不将整个官方 UI 重新纳入自有开发。常规内置交互不重复封装成第二套玩法协议。详细内容工作包见[游戏内容设计](gameplay-content.md)。
