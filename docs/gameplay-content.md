# 游戏内容与业务开发分工

本文件把“游戏系统”拆成官方机制、产品配置、自有规则和客户端展示。当前为技术实施规格，尚未确定完整策划、数值或原创资源量。统一分类见[复用与开发边界](reuse-development-matrix.md)，实施任务见[backlog](backlog.md)。

## 内容规格先于实现

SPEC01 在现有切片范围内建立产品规格及能力映射，离线部分可先开展；官方映射由 R07 补齐。每项规则说明目标玩家、触发、条件、数据/资源来源、奖励/成本、异常场景、所用内置能力与差异。未确认职业数量、地图规模、经济参数、发行地区或渠道时登记待决事项，不把示例填成产品决策。

产品工作不是重写角色、战斗或背包；它是配置这些系统、编写它们未覆盖的玩法、生产对应 UI/资源并验证实际效果。内容制作和资源授权仍是独立交付，不能因“机制复用”省略。

| 主城/野外/副本各一张 | 地图、移动、怪物/NPC、切图 | 出生/传送、怪物刷新、NPC、资源引用 | 副本进入/退出条件与必要事件脚本 | V01/V03；进入、战斗、返回和重登 |

| 背包/装备/仓库 | 资产容器、拾取、穿戴和保存 | 物品属性、容量、绑定/堆叠 | 基础切片先继承 UI；新增养成在 G02 实施 | V03/R06；状态和故障窗口核对 |
| NPC/任务/商城 | 可用的任务/交互/购买机制 | 对话、任务条件、商品、价格与奖励 | 一个自定义交互及界面、服务器校验 | V02/V03；正常、重复和非法输入 |
| 账号与沙箱购买 | 官方登录、可用的充值/发货链路 | 测试身份与商品映射 | 必要的账号/订单映射与查询、对账 | V05/P02—04；沙箱证据不代表真实付费 |
| 资源更新 | 官方热更/缓存/打包链路 | 首包/增量/静默清单与基包 | 清单/BOM、官方工具封装与灰度流程 | V04；真实更新、错包、断下载和回退 |

切片用一个 NPC 任务和一次受控活动领取验证业务链路；高价值奖励须服从 R06 的能力结论。全部基础 UI 美化、全职业、完整赛季、拍卖和复杂跨服不扩入 M3，除非正式调整范围。

## 每项玩法的开发流程

1. SPEC01/R07 对照规则与官方能力，填写[功能分工模板](templates/feature-scope.md)，先列能配置的部分。
2. 数据 schema 与官方字段映射进入 T02，ID/消息进入 T03，资源来源进入 T05。
3. 新规则写入 `ER` 领域模块；官方调用通过 runtime/受控入口集中，不侵入内核或数据库。
4. 业务消息只传操作意图；服务端决定条件、成本、奖励与结果。普通内置交互不额外包一套自有协议。
5. 确有新界面才生成 GUIExport，手写行为独立管理；继承官方基础 UI 时只修改受支持覆盖点。
6. 校验与离线逻辑通过后，在同一 BOM 的官方环境重放正常、重复、非法、离线、重载、配置升级与故障场景。
7. 按真实证据验收，登记限制和回滚边界；未覆盖的部分保持待前置。

## 资产、时间与状态的必填规则

| 类别 | 规格必须回答 |
|---|---|
| 资产操作 | 权威归属、消耗/产出、原子范围、持久时点、业务幂等键、结果查询、崩溃后的 UNKNOWN/核对路径 |
| 任务/活动 | 服务端时间、周期 ID、重复领取、跨日、离线补偿、重登/重载、活动版本切换 |
| 交易/养成 | 价格/配方快照、物品绑定、库存不足、背包满、部分执行、重复请求与失败恢复 |
| 跨服 | 当前写归属、迁移期间操作、结算方、超时/返回、重复迁移及奖励核对 |
| 客户端 | 加载/空数据/错误/处理中状态、回包迟到、关闭解绑、重连刷新、PC/移动布局 |

不把变量持久化与发奖默认视为同一事务。R06 未能证明安全执行时，先采用满足要求的内置操作，或限制沙箱/功能范围；该功能不能按商业可用验收。

## 内容和资源交付

源表、脚本、UI 行为进入 Git；GUI 导出与客户端/服务端投影由锁定构建生成，禁止手改生成件。供应商原始表/素材保留版本和原始哈希，自有覆盖差异单独登记。合法的大资源放受控制品库，Git 保留来源、逻辑路径、哈希、许可及分包清单。

任务验收包括规格、内容文件、公开能力映射、离线报告、官方场景报告和剩余限制。美术/音效/文案的制作量由产品范围单列估算，资源转换完成不能代替资源制作完成。
