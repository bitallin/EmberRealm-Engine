# 项目定义与范围

## 目标与定位

名称：**烬界引擎 / EmberRealm Engine**；代号：Project Ember；简称：ERE；命名空间：`ER`；未来仓库/制品前缀：`emberrealm-*`。

第一阶段把已获授权的官方 996 运行时接入一套可复用的游戏研发与运营工程平台。核心成果是：稳定的 Lua 适配与玩法模板、内容契约、自动校验与构建、版本 BOM、发布/恢复机制、测试基线、外围业务与运营能力。用一个最小玩法样本证明全链路，而非仅整理安装说明。

用户附件先评估了独立引擎，随后明确要求尽量使用 Lua、M2 与已有逻辑，避免重写。当前实施以附件后半部分的路线 A 为准。平台名称不代表已经拥有 M2 或客户端底层源码。

## 首个可验收版本

`0.1 Ash` 为垂直切片版本标签，不是当前软件版本：

| 范围 | 交付要求 |
|---|---|
| 环境 | 锁定一个官方分支、引擎/客户端/数据库/工具组合；开发与测试隔离 |
| 内容 | 一个职业、主城/野外/副本各一张，基础技能、怪物、掉落、任务 |
| 状态 | 背包、装备、仓库、死亡复活、退出重登保存 |
| 扩展 | 自有 Lua 模块、至少一个自定义 UI 和消息契约 |
| 发布 | 自动构建、BOM、一次真实资源热更新和回滚验证 |
| 平台 | 账号映射原型、支付沙箱与受控奖励链路，不接真实付费 |
| 运维 | 日志、备份恢复、基础监控、故障记录 |
| 证据 | 固定场景重放、结果报告、安装与复现步骤 |

PC 先验证，Android 与 iOS 分阶段接入；M0 记录实际可获得的官方客户端范围。M3 前至少 PC 完成链路，若 M0 获得两端则验证同服互动。H5 为可选后续范围，不作为首版阻塞项。

## 商业版本范围

在垂直切片通过后，扩展职业成长、装备养成、Boss/副本/活动、经济系统、行会和社交、赛季与排行、新手引导、跨服活动；完成多端弱网、渠道适配、支付补单、GM/客服、反刷规则、封测和发布。具体内容量、发行地区、容量和付费设计在 M3 前形成单独产品规格，不以本技术规划替代策划。

## 首期不纳入

完整底层源码替换、私有协议兼容、全量 TXT/GOM/GEE 脚本兼容、一键迁移任意历史版本、无缝分布式大世界、原创美术的完整生产、尚未确认的官方平台能力。后续独立内核只能经过新的决策与里程碑纳入。

## 成功指标

| 维度 | 首期目标及口径 |
|---|---|
| 可复现 | 同一源码、配置和官方制品哈希可重新构建；新 Windows 环境目标 2 小时内完成标准部署，不含大包下载与许可办理 |
| 可追踪 | 运行实例、客户端、数据、脚本和资源可关联唯一 release ID |
| 数据正确 | 重登状态一致；重复业务请求无重复领取；故障结果可查明 |
| 可发布 | 热更和灰度能检验兼容性；不兼容数据库改动有明确恢复路径 |
| 可恢复 | 实际完成至少一次隔离恢复演练，达到经确认的 RPO/RTO |
| 可扩展 | 一项新玩法走配置与适配层，不侵入官方内部结构 |
| 性能 | 用声明硬件、地图/人数/脚本版本的报告定义容量，无未经测量的承载承诺 |

## 参与责任

Codex 可承担文档、代码、脚本、自动化、测试与排查；授权获取、真实支付商户、发行账号、用户数据使用条件与实际环境权限由项目持有人提供。AI 工作速度不替代官方交付、环境验证和发布资质。
