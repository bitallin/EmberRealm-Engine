# 复用与开发边界总表

更新：2026-10-08；依据：[本轮官方内核同构方案](reference/runtime-reuse-proposal.md)、[技术路线](technical-route.md)与 ADR-0001/0003。本表是任务拆分的统一口径，当前只完成设计；所有官方复用项均未通过本项目锁版环境验证。

## 分类与交付口径

| 分类 | 含义 | 本项目交付 | 是否开发该底层组件 |
|---|---|---|---|
| 复用 | 合法取得官方组件、基础系统或工具，直接使用其已有机制 | 许可/版本/哈希清点、安装配置、黑盒验收、运维说明 | 否；接入和验证仍有工作量 |
| 配置 | 在已有系统内制作产品数据、规则参数与资源 | 源表、字段映射、内容包、配置校验与回归 | 不重写机制；内容必须制作 |
| 适配 | 对公开能力做薄封装、接入或差异补足 | ER runtime、入口/消息映射、UI 行为、工程封装、集成测试 | 开发边界层，不复制底层状态 |
| 自研 | 产品特有规则或官方未覆盖的工程/外围业务 | 自有 Lua、schema/校验器、BOM/流水线、必要平台模块 | 是；先明确官方差异和验收 |
| 后置 | 不在当前发行范围，或仅在能力不足时评估 | 需求证据、替代方案与新 ADR | 当前不启动实现 |

分类针对交付物，同一功能可包含多类工作。例如“装备”同时有官方装备机制（复用）、属性和掉落（配置）、新增养成规则（自研）。任务标注“配置+适配”不意味着需要重写背包。能力证据独立于分类：选择复用不等于已取得包、已获许可或已集成。

## 官方底层：直接复用，不列为内核研发

| 组件/机制 | 处理方式 | 本项目仍需做 | 明确不做 | 任务/能力证据 |
|---|---|---|---|---|
| M2Server 区服运行时 | 复用 | 清点、锁版、启停、配置、监控、容量测试 | 自建世界主循环、AOI、战斗底层 | R01/R02、ENV01/ENV02、QA04 |
| 登录/游戏网关、角色/DB 服务 | 复用 | 实际进程/端口/连接图、身份接入、故障恢复 | 新网关、官方协议逆向与旁路登录 | R01/R02、P02、CAP11 |
| 启动器/控制器 | 复用+适配 | 使用受支持控制方式，封装启停与健康检查 | 重写官方控制器内部实现 | ENV02、CAP11 |
| Windows/Android/iOS 原生内核 | 复用 | 核实交付端、SDK/签名、输入/UI/设备回归 | 渲染、输入底层、原生网络栈重写 | R01、C01—04、CAP12 |
| Lua/LuaJIT 运行时 | 复用 | 版本/语法/线程/加载/生命周期探针 | 更换内置 VM 或自行升级 Lua | R03/R05、CAP01/CAP05 |
| SQL Server 游戏基础库与升级工具 | 复用 | 官方初始化/迁移、版本摘要、备份与恢复 | 复制数据库服务、擅改字段、平台直接写资产 | ENV03、CAP18 |
| GUI 控件、编辑器、基础 UI | 复用+适配 | 原界面继承、自定义页面导出、事件与布局适配 | 重写控件系统、修改生成文件 | V02、C01—03、CAP07 |
| 表格/资源转换与打包工具 | 复用+适配 | 锁工具、字段映射、输入输出追踪、自动化封装 | 自造官方资源格式或客户端解析器 | T02/T06、CAP08 |
| 热更、微端、静默下载、资源缓存 | 复用+配置+适配 | 分包清单、基包关系、灰度、旧端/断网/回退验证 | 新客户端更新器、未验证的差分格式 | V04/C05、CAP09 |
| 官方公共资源 | 条件复用 | 来源、许可、发布范围、格式与性能核验 | 将可下载等同可商用/可再分发 | T05/V01、R01 |

## 游戏系统：复用机制，制作内容与差异规则

| 系统 | 直接复用什么 | 必须制作/配置什么 | 何时开发 Lua/UI | 任务/能力证据 |
|---|---|---|---|---|
| 职业、成长、角色基础属性 | 角色与属性计算的官方机制 | 职业范围、成长曲线、属性表、上限 | 产品新增成长条件/展示，公开接口覆盖后扩展 | SPEC01、V01/G01、CAP13 |
| 移动、地图、寻路、传送 | 地图运行与角色移动机制 | 主城/野外/副本地图、出生点、传送与限制 | 新副本进入/离开规则与页面 | V01/V03/G03、CAP13 |
| 战斗、技能、Buff | 官方战斗执行、技能与 Buff 系统 | 效果、冷却、消耗、范围、数值、资源 | 新技能组合/触发条件；无需改底层时才扩展 | V03/G01、CAP14 |
| 怪物、NPC、刷新、掉落 | 怪物/NPC/掉落基础机制 | 怪物表、刷新点、掉落表、NPC 与剧情 | 自定义 NPC 交互、特殊 Boss/任务脚本 | V01/V03/G03、CAP13/CAP14 |
| 背包、装备、仓库、拾取 | 存储/穿戴/拾取和官方持久化 | 物品属性、容量、绑定/堆叠/掉落规则 | 新增养成/合成/回收差异和 UI；先验证资产边界 | V03/G02、CAP13/CAP06 |
| 任务、新手引导 | 可用的任务/导航/引导机制 | 任务链、完成条件、文案与奖励 | 官方未覆盖的任务条件、引导步骤和提示 | V03/G05、CAP15 |
| 商城、交易、摆摊、拍卖 | 官方购买/交易机制与资产操作 | 商品、价格、交易限制、手续费 | 新经济规则与跨区展示；不复制游戏资产交易库 | G04、CAP16/CAP06 |
| 组队、行会、好友、邮件 | 内置关系与邮件机制 | 权限、门槛、奖励配置和文案 | 新活动/社交展示，邮件资产须验证可靠性 | G05、R07、CAP15 |
| 排行榜、赛季、开服活动 | 内置排行/活动中已覆盖的部分 | 排序/重置周期、开服日程、结算与奖励 | 自定义赛季/跨区汇总；外部榜只作展示/统计 | G03/G04/P07、CAP16 |
| 跨服地图与基础链路 | 官方跨服 M2、迁移与返回机制 | 分组、地图、进入限制、活动规则 | 自定义跨服活动与恢复核对，仍服从官方写归属 | X01—03、CAP10 |
| 挂机、自动战斗、反刷 | 可用的官方自动战斗及反外挂 | 开放条件、频率、收益限制和风险规则 | 新业务检测与处置、误报评估 | G05、R08、CAP17 |

基础系统是否存在、是否授权、能否公开调用、能否满足规则分别验证。R07 产出逐系统差异清单；已覆盖部分不再产生同名“从零开发”任务，未覆盖部分按配置 → API → Lua → UI → 外围服务顺序选最小实现。

## 外围平台：先复用官方链路，再补必要模块

| 能力 | 默认处理 | 确有差异时开发 | 前置/任务 |
|---|---|---|---|
| 官方账号、渠道、区服入口 | 复用受支持登录/渠道链路 | 账号映射、渠道适配、区服展示；不另造绕过认证的账号体系 | R01/R03/R08、P02/C04 |
| 官方订单/充值/补单 | 先验证并复用内置发货、幂等和结果查询 | 未覆盖渠道的订单/回调、映射、对账、受控 outbox；不得建设第二条并行发货链 | R06/R08、P03/P04、CAP19 |
| CDK/礼包 | 有合适内置能力则配置+接入 | 跨渠道统一活动、兑换规则、记录与奖励命令 | R08/P05、CAP20 |
| GM 后台、工具服、封禁与客服 | 官方能力优先 | 必要的统一只读查询、RBAC、审计、固定命令；官方不支持的写操作不开假入口 | R08/P06、CAP20 |
| 公告/活动配置/版本与区服管理 | 内置发布/后台可用部分复用 | 跨区配置发布、BOM 关联、审批记录/审计、差异能力 | R08/P07/T07/T09 |
| 排行汇总、埋点、留存/付费分析 | 原生统计/日志可用部分接入 | 统一事件、去重、统计口径与报告 | R07/R08/P07 |
| 反外挂、CDN/对象存储 | 条件复用官方或已授权服务 | 规则配置、日志采集、业务风控、清单/灰度/缓存验证 | R08、G05/C05/OPS01、CAP17 |

Go/PostgreSQL/React 是需要自有服务时的拟定实现方向，不代表必须先搭全部平台。官方服务若满足契约，任务验收可以交付接入/配置和证据；数据模型仅对自有真值及必要审计映射生效。

## 工程能力：自有工程封装，底层工具优先复用

| 工作 | 本项目开发/维护 | 可复用工具/服务 | 任务 |
|---|---|---|---|
| 数据生产与校验 | schema/ID/引用、双端投影、错误报告 | Excel 编辑与官方转换器 | T02/T03 |
| Lua 与编码检查 | 锁版语法配置、严格转换/往返检查、安全规则 | 成熟静态检查工具，不另写 Lua 编译器 | T01/T04/QA01 |
| 资源与来源校验 | 路径/大小写/来源/哈希/预算清单 | 官方资源转换打包工具 | T05/T06 |
| BOM 与构建 | 版本兼容锁、输入输出追踪、官方工具调用封装 | Git、CI Runner、官方工具 | T06—08 |
| 部署、健康、灰度与回滚 | 环境模板、流程脚本、版本核对、兼容判断 | 官方控制器、OS/部署工具、制品服务 | ENV01/ENV02/T09/OPS03 |
| 监控与备份恢复 | 日志/指标接入配置、告警规则、恢复/对账 runbook | 现成日志/告警平台、数据库备份工具 | ENV03/OPS01/OPS02 |
| 自动回归与容量 | 固定角色、场景、官方兼容自动化、故障报告 | 官方测试客户端或受支持控制工具 | QA01—05 |

“自研工程能力”指本项目流程、校验、脚本和集成；不要求重写 Git、CI、监控平台、SQL 备份器或第三方通用工具。

## 后置与变更门槛

H5 在确认官方交付与发行需求后再纳入；独立 M2、客户端内核、协议、网关、数据库服务、热更/授权体系属于路线 B，当前无实现任务。只有真实限制触发[内核替换门槛](technical-route.md#内核替换门槛)后，经新 ADR、范围和迁移计划立项。

每项需求先填写[功能分工模板](templates/feature-scope.md)，关联系统、任务、配置、适配、自研差异、能力证据、失败/恢复和验收。验收分三层：官方机制可用、自有差异正确、组合运行可靠；最后一层通过才可标记对应集成任务完成。未获得包时只记文档或离线验证，不称“已复用完成”。
